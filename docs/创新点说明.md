# 文策析｜办公文档任务智能拆解与导出工具 · 创新点说明

## 创新点一：不依赖大模型的"离线办公 AI 引擎"

当前多数 AI 办公产品强依赖云端大模型，存在三重门槛：**费用门槛、网络门槛、数据安全门槛**。本项目的核心创新是把办公场景最高频的六类能力（分析、提取、待办、计划、报告、检查）用一套**自研中文规则引擎**在本地完整实现：

- 基于 n-gram 词频 + 垂直词库加权的无分词关键词算法；
- 覆盖绝对/相对日期、12 小时制时间、金额单位归一的实体抽取；
- 以动作动词和责任句式为线索的待办识别；
- 面向工作日的自动排期与里程碑生成；
- 可解释的矛盾/遗漏规则检查。

**离线、免费、数据不出本机**，在政企内网、保密场景、无网络环境中具有不可替代的价值。

## 创新点二：从"公文"到"可导入成果"的闭环

传统大模型产品的输出是"一段话"，而办公真正需要的是"可执行的结果"。本项目定义并实现了完整闭环（与计划书"文本读取→要素抽取→结构化导出"一致）：

```
Word/文本/录音 → 读取解析 → 要素抽取 → 任务清单 → 计划排期 → 一致性检查 → CSV 任务表 / ICS 日历导出
```

- 直接上传会议纪要 .docx，零依赖本地解包（支持 stored/deflate），坏文件、旧版 .doc 给出明确提示；
- 每个环节的输出都是**结构化数据**：待办带责任人、优先级、截止时间、置信度与原文出处；
- 最终产物是**可直接导入日历与表格软件的标准文件**（.ics 含 VTIMEZONE/提醒、.csv 带 BOM），而非对话文字，用户无需再把模型回答"翻译"成行动。

## 创新点三：面向中文办公的"一致性检查官"

大模型容易一本正经地忽略材料中的矛盾，而本项目把办公中最常见的**事实性错误**规则化：

1. 同一预算/费用前后金额不一致（自动归一化万元/亿元后比对）；
2. 同一指标出现不同百分比；
3. 同一句话中"已完成"与"未完成/延期"并存；
4. 时间变更（原定 X 改为 Y）未明确以哪个为准；
5. 待办缺责任人、缺截止时间、截止日期已过；
6. 会议通知缺时间、地点、参会范围；
7. 高度重复的段落。

检查结论**逐条附原文依据**，可解释、可核对，可直接作为材料质检工具使用。

## 创新点四：相对日期智能解析与工作日排期

中文办公材料中的时间表述大量使用"本周四""月底前""下周三"等相对日期，通用工具难以处理。本项目：

- 以当前日期为基准，精确解析"今/明/后/大后天、本周/下周 + 星期、月底、月初、年底"等表述；
- 自动完成缺年日期跨年推断、非法日期过滤；
- 排期自动跳过周末、避让已占用日期、把明确截止日钉在对应日期；
- 对已过期的截止日期立即告警。

## 创新点五："规则保底 + 大模型增强"的诚实 AI 架构

系统不做"非此即彼"：

- **本地引擎保底**：没有密钥、没有网络时，所有核心功能照常工作；
- **大模型可选增强**：用户自填兼容 OpenAI 接口的地址和密钥，用于报告语言润色；
- **诚实原则**：未配置时明确提示使用本地引擎；调用失败时如实显示错误码和原因，绝不伪造模型回答；
- 密钥仅保存在用户本机浏览器，系统不收集、不经手。

这是一种可落地、可审计、成本可控的 AI 应用架构，适合比赛演示与真实交付。

## 创新点六：零编程基础用户的"零依赖交付"

- 服务端仅使用 Node.js 内置模块，**不需要 `npm install`**，不存在依赖安装失败、供应链投毒等问题；
- 双击 `启动项目.bat` 即可运行；脚本自动检测环境，缺失 Node.js 时自动降级为静态网页模式；
- 项目不依赖任何 CDN 资源，U 盘拷贝、内网拷贝均可运行；
- 核心引擎采用 UMD 同构设计，浏览器与 Node 测试环境共用一份代码，18 项自动化测试保证质量。
