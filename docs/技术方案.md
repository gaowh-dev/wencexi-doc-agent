# 文策析｜办公文档任务智能拆解与导出工具 · 技术方案

## 一、总体架构

系统采用"**轻量本地服务 + 文档解析（Word 解包）+ 本地中文分析引擎 + 智能体执行层 + 浏览器交互层**"的结构，运行时零第三方依赖。

```
┌────────────────────────────────────────────────────────┐
│                    浏览器（前端交互层）                  │
│  index.html / styles.css / app.js / charts.js          │
│  ├─ 结果标签页、数据看板、进度跟踪、历史管理、导出         │
│  ├─ 录音纪要（MediaRecorder + Web Speech）               │
│  ├─ localStorage（历史任务）；密钥仅 sessionStorage       │
│  └─ 可选：OpenAI 兼容接口直连（AI 增强，用户自带密钥）    │
└───────────────▲────────────────────────┬───────────────┘
        .docx 上传（POST 原始字节）         │ 默认零网络请求
┌───────────────┴────────────────────────▼───────────────┐
│              Node.js 本地服务（src/server.js）           │
│  内置 http/zlib；静态托管；/api/parse-docx；安全头；       │
│  127.0.0.1 绑定；路径白名单防穿越；端口自动避让；自动开页  │
└───────────────────────────┬────────────────────────────┘
┌───────────────────────────▼────────────────────────────┐
│              本地核心（src/core/，浏览器/Node 同构）       │
│  docx-parse.js（Word 解包）→ engine.js（分析引擎）        │
│  tools.js（CSV/ICS/消息等交付工具）→ agent.js（状态机）    │
│  adapters/mobileclaw.js（未连接显式拒绝，禁止伪造）        │
└────────────────────────────────────────────────────────┘
```

设计要点：

1. **同构引擎**：`engine.js` 使用 UMD 模式封装，浏览器挂到 `window.ZhiBanTong`，Node 下 `module.exports`，保证"浏览器跑的代码"和"测试覆盖的代码"完全一致；
2. **零依赖原则**：服务端只用 Node 内置模块，前端不引入任何 CDN/框架，离线环境可运行、可交付、可复现；
3. **无构建步骤**：不需要打包编译，文件即部署，便于零编程基础用户使用与二次开发。

## 二、核心引擎算法设计

### 2.1 文本切分与统计

- 段落：按连续空行切分；
- 句子：按 `。！？；!?;` 与换行切分，并处理序号与列表符号前缀；
- 统计：全角/半角空白剔除后的字数、CJK 字数、数字数、平均句长、预计阅读时长（按中文约 400 字/分钟）。

### 2.2 关键词抽取

采用"**n-gram 词频 + 停用词过滤 + 办公领域词库加权 + 包含关系消重**"的无词典依赖方案：

1. 抽取所有连续 CJK 串；
2. 生成 2~4 字 n-gram，剔除首尾为停用字（的、了、在、是、请、需……）的片段；
3. 词频统计，3 字以上片段权重 ×1.6；
4. 约 150 个办公领域词（会议、里程碑、验收、整改、回款……）命中加权 ×2.2；
5. 按分排序后，若低分短词被高分长词包含则剔除。

优点：无需分词库即可在垂直领域取得稳定效果。

### 2.3 抽取式摘要

对句子按以下信号打分，取 Top-N 并恢复原文顺序：

- 关键词覆盖密度（+1.4/次）；
- 摘要指示词（因此、综上、要求、必须、决定、一是/二是……）（+2.5）；
- 首句、尾句位置加成；
- 过短句惩罚，避免标题/碎片进入摘要。

### 2.4 实体抽取（规则 + 词库）

| 实体 | 方法 |
| --- | --- |
| 绝对日期 | 正则覆盖 `2026年10月19日`、`2026-10-19`、`2026/10/19`、`2026.10.19`；做日期合法性校验（避免 2 月 30 日） |
| 缺年日期 | `10月19日` 按基准年解析，已过则自动顺延到下一年 |
| 相对日期 | 今天/明天/后天/大后天；本周/下周 + 星期 X；周 X；月底/月初/年底 |
| 时间 | `10:30`、`上午10点`、`下午3点半`，自动做 12/24 小时换算 |
| 电话/邮箱/网址/证件号 | 带边界约束的正则 |
| 金额 | 匹配数字 + 单位（元/万元/亿元/美元/港元…），统一折算人民币近似值 |
| 组织机构 | 后缀驱动（公司/集团/局/院/委员会/事业部/项目组……）+ 前向捕获 |
| 人物 | 百家姓 + 称谓（总/经理/总监/工/先生/女士……），以及"负责人：X" |
| 地点 | 全国省级与重点城市词库 + 场所模式（会议室/大厦/X 层/X 室/酒店） |
| 截止时间 | 含"截止/截至/最迟/最晚/之前/到期"等线索词的句子中的日期时间 |

### 2.5 待办事项识别

- 触发模式：祈使/情态线索（请、务必、必须、需要、建议、尽快……）后接动作动词（约 90 个：完成、落实、提交、对接、整改、验收……）；或句首直接为动作动词；
- 责任人解析：按"由 X 负责 / X 负责 / 请 X 于… / 姓氏+称谓 / 部门名词"多组正则依次尝试，并清洗部门前缀与头衔后缀（如"研发部张伟工程师"→"张伟"）；
- 截止时间：句内日期 + 时间；
- 优先级：紧急/务必/立即/当天 → 高；建议/拟/视情况 → 低；其余 → 中；
- 输出按优先级、截止时间排序。

### 2.6 任务计划生成

- **阶段划分**：按动作动词把任务归入四个阶段——准备与梳理、执行与推进、交付与验收、复盘与总结；
- **工作日排期**：带明确截止日期的任务"钉"在对应日期；其余任务按优先级依次填入空闲工作日（自动跳过周末）；
- **里程碑**：所有带明确截止日期的任务汇总为里程碑，并对已过期日期给出红色告警；
- 输出计划周期、占用工作日、分阶段排期表。

### 2.7 一致性与遗漏检查

| 检查项 | 规则 |
| --- | --- |
| 金额冲突 | 抽取"名词 + 数值 + 单位"，按名词归组并归一化（万元→元），同一名词出现不同金额 → 高风险矛盾 |
| 百分比冲突 | 同一指标（XX 率/占比/增长/满意度…）出现不同数值 → 中风险 |
| 状态矛盾 | 同句同时出现"已完成/已上线"与"未完成/延期/未通过" |
| 时间变更 | 同句出现"原定/改为/延期"与两个日期 → 提醒确认 |
| 要素遗漏 | 待办缺责任人（中）、缺截止时间（低）、截止日期已过（高） |
| 会议完整性 | 会议类材料缺日期/时间/地点/参会范围分别提示 |
| 内容重复 | 句子级字符集合 Jaccard 相似度 > 0.85 判为重复 |

每条结论都输出：级别（矛盾/遗漏/重复/建议）、严重度（高/中/低）、说明、原文依据。

### 2.8 报告生成

基于模板管线，把统计、摘要、实体、待办、计划、检查结果组装为七章节 Markdown 报告；内置轻量 Markdown 渲染器（标题/表格/列表/引用/加粗/代码/分隔线）直接在浏览器呈现。

### 2.9 Word（.docx）读取

DOCX 本质是 ZIP 包，正文位于 `word/document.xml`。`docx-parse.js` 用 Node 内置 `zlib` 实现最小 ZIP 读取器（支持 stored/deflate），不引入任何第三方库：

1. 定位 End of Central Directory，遍历中央目录找到 `word/document.xml`；
2. 按本地文件头取出压缩数据，`zlib.inflateRawSync` 解压；
3. 按 `<w:t>`（文本）、`<w:tab/>`（制表）、`<w:br/>`（换行）、`</w:p>`（段落）把 XML 还原为纯文本，解码 XML 实体；
4. 异常（非 zip、缺正文、旧版 .doc、正文超 5MB）抛出明确错误，前端提示用户另存为 .docx。

服务端 `POST /api/parse-docx` 接收原始字节（上限 10MB），解析在内存中完成、不落盘，返回 JSON；静态模式（file://）下前端明确提示改用服务模式。

## 三、前端设计

- 原生 JS，无框架，事件驱动；单一状态对象 `state.result` 持有完整流水线结果；
- 六个标签页各自渲染；勾选待办会回写状态并实时重算进度、重生成报告；
- 历史记录使用 localStorage 结构化存储（上限 50 条，含原文与完整结果，可脱离原文重新载入）；
- 导出使用 Blob + URL.createObjectURL 生成下载；
- 可选 LLM 调用使用浏览器 `fetch` 直连用户自填的 OpenAI 兼容接口；任何失败（未配置、401、网络错误、空返回）均如实提示，不伪造。

## 四、服务端设计

- 使用 `http/fs/path/zlib`，零第三方依赖；
- 安全：URL 解码后 `path.normalize`，并校验目标路径必须位于 `public` 或 `src` 白名单目录内，防目录穿越；
- 所有响应带 CSP、nosniff、DENY frame、Referrer-Policy、Permissions-Policy 安全头；
- MIME 表覆盖常用静态资源；
- 端口占用时自动 +1 重试；启动后自动调用系统浏览器；
- 提供 `/api/health` 健康检查与 `/api/parse-docx` Word 解析接口（10MB 上限、异常返回明确错误、文件不落地）。

## 五、质量保障

- `tests/engine.test.js`（21 项）：分句、日期（含相对日期）、时间、实体、关键词、摘要、分类、待办、排期、矛盾、遗漏、重复、报告、空输入等；
- `tests/tools.test.js`（12 项）：CSV/ICS/派任务消息、智能体规划/执行/跳过/失败、MobileClaw 适配、空待办；
- `tests/docx.test.js`（4 项）：真实 .docx 夹具解析、Word→引擎任务拆解、坏文件报错、XML 实体；
- `tests/eval/run-eval.js`（8 项）：16 个手工标注语料的召回/精确率阈值；
- `tests/browser/headless-check.js`（27 项）：真实点击、真实 Word 上传、真实下载、看板、手机视口、JS 错误；
- 以固定基准日期保证相对日期测试可复现；关键结论均可追溯到原文依据。

## 六、可扩展方向

1. 接入更强的分词/词性库（如 jieba）提升关键词与人名识别；
2. 支持旧版 .doc（OLE 复合格式）与 PDF 文本提取、报告导出 .docx；
3. 多人协同：把 localStorage 换成轻量数据库（SQLite）；
4. 官方 MobileClaw SDK 到位后，把 .ics/CSV/消息复用为真机日历/消息动作；
5. 模型层抽象：把本地规则引擎与 LLM 组装为可切换的 pipeline，实现"规则保底、模型增强"。
