## 三、五维评分（保守）

### A. 创新价值：22 / 30（初版 12）

**得分依据**
- 把通用"材料分析"升级为"规划→确认→执行→自检→交付"的可执行智能体，且在零依赖、纯离线条件下实现，场景聚焦"会后任务落地"，与普通聊天机器人有实质区别。
- 诚实的通道设计：MobileClaw 未连接时显式报错、不模拟；以可导入的标准格式文件（.ics/CSV）构成真实可执行替代。
- 录音→转写→本地引擎→产物，以及数据看板（时间线/置信度/责任人分布）强化了端到端闭环。

**主要缺陷**
- 规划是确定性规则而非自主决策，不具备动态 replan 与多轮工具探索；
- 缺少真机端动作（MobileClaw 未接入），"手机智能体"故事目前到文件导入为止；
- NLP 为规则引擎，泛化能力未在大规模真实语料上验证。

**改进建议**：官方 SDK 到位后按 `adapters/mobileclaw.js` 顶部契约接入 `calendar.create/message.send/reminder.create`，复用现有确认与自检流程，即可把闭环延伸到真机。

### B. 实用价值：21 / 25（初版 15）

**得分依据**
- 产物真实可用：`.ics` 可被手机/Outlook/飞书日历导入（含 VALARM/时区），CSV 带 BOM 可直接导入飞书/钉钉/Excel，派任务消息可直接粘贴；
- 目标用户（项目经理/行政/参会人）明确，操作路径短（粘贴→分析→执行→下载）；
- 零安装依赖、双击启动、内网可用、数据不出本机，具备政企/保密场景落地条件。

**主要缺陷**
- 单人单机，无多人协同；消息仍需人工粘贴；
- 不支持 Word/PDF 读取（仅 txt/md/csv/log）；
- 缺少真实用户效率对比数据（无受试者，实测报告已如实声明）。

### C. 技术实现与复杂度：16 / 20（初版 12）

**得分依据**
- 引擎同构 UMD（浏览器/Node 跑同一份代码）；智能体为工具注册表 + 注入式执行器 + 产物自检，可在 Node 测试中用假执行器完整验证；
- 41 项 node:test 全部通过；自研零依赖 CDP 端到端检查 27 项全部通过（真实点击、真实下载、手机 390 视口、零横向溢出、零 JS 错误）；
- 16 个手工标注语料评测：待办召回/精确率、责任人、泛称、日期、人名召回均 100%，假人名 0；单篇约 2.39 ms。

**主要缺陷**
- 规则引擎覆盖词库有限，复杂长句/跨段指代仍是弱项；
- 可选 LLM 路径未用真实密钥实测（标注"尚未验证"）；
- MobileClaw 适配层为空壳契约；无 CI 流水线。

### D. 用户体验与交互：13 / 15（初版 11）

**得分依据**
- 8 个标签页分工清晰，空态、徽标、原文出处、信息缺口、执行步骤、自检结果一目了然；
- 待办可直接行内编辑，看板（进度环/分布图/时间线）让全局状态可视化，手机视口实测可用；
- 录音页隐私提示与降级路径完整。

**主要缺陷**
- 结果信息密度偏高，首次使用需要引导；
- 看板为静态 SVG（无交互钻取，刻意保持零依赖）；
- 静态模式与服务模式下载体验略有差异。

### E. 安全合规：9 / 10（初版 7）

**得分依据**
- 默认仅绑定 127.0.0.1；所有响应带 CSP、X-Frame-Options、nosniff、Referrer-Policy、Permissions-Policy；路径白名单防穿越（实测）；
- API 密钥仅存 sessionStorage（关闭即清，旧 localStorage 自动迁移删除）；外发前二次确认目标与范围；
- 派任务消息只复制不发送；录音转写为可勾选选项并明示可能经浏览器厂商服务；
- 无任何第三方依赖，无供应链风险。

**主要缺陷**
- 无自动化安全扫描；文件读取大小上限仅前端约束（5MB）。
